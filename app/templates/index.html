How it works

Two separate workflows, clearly labeled.

Live monitoring uses file-change rules. SILRAD evaluates labeled dataset events offline.

Live file monitoring

Observe changes. Review alerts.

  1. 01Choose a source. Browser folder, app-server folder, or Windows endpoint agent.
  2. 02Record file activity. Track file creates, modifications, deletes, and relative paths.
  3. 03Apply burst rules. Compare activity counts with your configured thresholds.
  4. 04Review and respond. Acknowledge alerts; quarantine is manual for browser/agent files and optionally automatic for the server folder.
Offline SILRAD benchmark

Evaluate labeled events.

  1. 01Prepare published data. Download the SILRAD training and test files to the server.
  2. 02Select a threshold. Use the training split only.
  3. 03Evaluate the held-out stream. Predict each event before using its known label for the next update.
  4. 04Review metrics. See precision, recall, false alarms, and missed events for this dataset.
Research scope

Know what each result means.

Clear limits help prevent a research signal from being mistaken for a security verdict.

What RansomShield does

  • Records file activity from the selected monitoring source.
  • Raises review alerts when configured burst rules are crossed.
  • Provides manual quarantine options and optional server-folder auto-quarantine.
  • Evaluates labeled SILRAD data in a separate offline workflow.

What results do not prove

  • A live alert does not confirm ransomware or identify the process responsible.
  • A rule score is not a probability of infection.
  • Dataset metrics do not prove live endpoint detection performance.
  • This research prototype is not a replacement for endpoint security software.
